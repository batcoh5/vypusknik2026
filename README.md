# Выпускник Краснообска 2026 — сайт голосования

Сайт народного голосования ежегодного конкурса «Выпускник Краснообска» (р.п. Краснообск).
Голоса защищены по принципам ДЭГ (vybory.gov.ru), оформление — в фирменном стиле группы конкурса
[ВКонтакте](https://vk.com/wkrasnoobskacontest).

- голосования создаются и запускаются из админ-панели — многоразово: создал → запустил → завершил → удалил → создал новое;
- голосуют по **номеру телефона с кодом из SMS** (SMS.RU): один номер — один голос в каждом голосовании;
- голос тайный: бюллетень заверяется **слепой подписью**, его нельзя связать с избирателем;
- выбор **шифруется в браузере** ключом комиссии, промежуточных итогов не видит никто;
- все бюллетени лежат в **открытом реестре** (цепочка блоков с хешами и подписями);
- после голосования выдаётся **квитанция**, по ней можно **проверить свой голос**;
- после завершения публикуется ключ расшифровки, и любой может **пересчитать итоги сам** в браузере.

## Запуск

Нужен Node.js 22.13 или новее. Внешних зависимостей нет: используются встроенные `node:sqlite` и WebCrypto, шрифты лежат в `public/fonts`.

```bash
ADMIN_TOKEN=придумайте-длинный-ключ SMS_RU_API_ID=ключ-sms-ru npm start
# сайт:    http://localhost:3000
# админка: http://localhost:3000/admin
```

Тесты: `npm test`.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт |
| `DATA_DIR` | `./data` (на Railway — путь Volume) | база (`vote.db`) с голосованиями и ключами комиссии, секрет (`secret.json`) |
| `ADMIN_TOKEN` | генерируется при старте | ключ для входа в `/admin` |
| `SMS_RU_API_ID` | — | ключ API из личного кабинета SMS.RU |
| `SMS_DAILY_LIMIT` | `500` | сколько SMS сайт может отправить за сутки (защита баланса) |
| `SMS_TEST` | — | `1` — SMS.RU только имитирует отправку (баланс не тратится) |
| `DEV_LOGIN` | — | `1` — код показывается на экране вместо SMS, для проверки на своём компьютере. **Не включайте на настоящем голосовании** |
| `MAX_VOTES_PER_IP` | `0` (без лимита) | сколько бюллетеней можно выдать на один IP в одном голосовании |
| `TRUST_PROXY` | — | `1`, если сайт стоит за nginx/балансировщиком |
| `SECURE_COOKIES` | — | `1` при работе по HTTPS |

В продакшене сайт должен работать по **HTTPS**: браузерная криптография (WebCrypto) доступна только в защищённом контексте.
Папку `data/` нужно резервировать и никому не передавать: в ней закрытые ключи комиссии.

## Запуск на Railway

1. **New Project → Deploy from GitHub repo** → выберите репозиторий. Railway сам поставит Node.js и запустит `npm start`.
2. **Volume — обязательно.** Railway при каждом деплое создаёт контейнер заново и стирает всё, что лежит внутри. Голосования, голоса и ключи сохраняются, только если к **сервису сайта** подключён Volume: сервис → **Settings → Volumes → New Volume**, путь `/data`. Сайт сам найдёт Volume (`RAILWAY_VOLUME_MOUNT_PATH`); если его нет — в логах и в админке появится красное предупреждение. Postgres сайту не нужен.
3. **Settings → Networking** — сгенерируйте адрес или подключите свой домен.
4. **Variables**:

   | Переменная | Значение |
   |---|---|
   | `ADMIN_TOKEN` | длинный пароль для `/admin` |
   | `SMS_RU_API_ID` | ключ SMS.RU |
   | `TRUST_PROXY` | `1` |
   | `SECURE_COOKIES` | `1` |

   `PORT` Railway задаёт сам. `DATA_DIR` не нужен — берётся путь Volume.

## Вход по SMS (SMS.RU)

1. Зарегистрируйтесь на [sms.ru](https://sms.ru) и пополните баланс (одно SMS — несколько рублей).
2. Ключ **api_id** — на главной странице личного кабинета. Укажите его в `SMS_RU_API_ID`.
3. В настройках SMS.RU можно ограничить число SMS на один IP — сайт передаёт им IP посетителя.

Как это устроено: человек вводит номер → браузер пару секунд решает «невидимую капчу» (вычислительную задачу — ботам массовая рассылка обходится дорого) → приходит SMS с 6-значным кодом (действует 5 минут, 5 попыток) → номер подтверждён.

Защита баланса: только российские мобильные номера (+7 9xx), не чаще 1 SMS в минуту и не больше 5 в сутки на номер, не больше 30 в час с одного IP, общий лимит `SMS_DAILY_LIMIT` в сутки.
Номер телефона не сохраняется: в сессии и в реестре избирателей — только HMAC, а слепая подпись не даёт связать номер с бюллетенем.

Проверить без SMS на своём компьютере: `DEV_LOGIN=1 npm start` — код покажется прямо на экране.

## Админ-панель (`/admin`)

1. **Новое голосование** — название, описание, номинации и варианты (имя + подпись, например школа и класс).
   Можно указать дату автоматического завершения.
2. **Запустить** — голосование появляется на сайте. После запуска номинации не меняются.
   Одновременно идёт только одно голосование.
3. **Завершить и подвести итоги** — приём голосов прекращается, бюллетени расшифровываются и подсчитываются,
   итоги и ключ расшифровки публикуются.
4. **Удалить** — голосование исчезает с сайта вместе с реестром и итогами. Посетители снова видят
   «Голосование ещё не началось». После этого можно создать новое.

Пока нет запущенного или завершённого голосования, на сайте написано «Голосование ещё не началось».

## Как защищён голос

```
Браузер избирателя                                Сервер
───────────────────                               ──────
1. token = случайные 32 байта
   blinded = H(token)·rᵉ mod n        ──────▶  2. этому избирателю в этом голосовании
                                                  подпись ещё не выдавалась?
                                      ◀──────     blindSig = blindedᵈ mod n
3. signature = blindSig · r⁻¹ mod n                (сервер не видит token)
4. ballot = ECIES(выбор, ключ комиссии)
5. {token, signature, ballot}         ──────▶  6. подпись верна, token не использован →
                                                  запись блока в цепочку, подпись блока
                                      ◀──────     квитанция = хеш блока
7. проверка хеша и подписи квитанции
```

- У каждого голосования свой комплект ключей комиссии (RSA-2048 для слепой подписи, ECDH P-256 для шифрования, ECDSA P-256 для реестра).
- **Слепая подпись** — RSA-FDH (схема Чаума). Реестр избирателей знает, кому выдана подпись, но не знает токен; реестр бюллетеней знает токен, но не знает, кому он выдан.
- **Шифрование** — ECDH P-256 + HKDF-SHA-256 + AES-256-GCM, открытый текст дополняется до 512 байт.
- **Реестр** — каждый блок содержит `SHA-256(index | время | хеш предыдущего | token | подпись | SHA-256(бюллетень))` и подпись ECDSA.
- Вся проверяемая математика — в `public/js/core.js`, его используют и сервер, и браузер.

## Защита от повторного голосования

- бюллетень выдаётся один раз на номер телефона в каждом голосовании — неважно, с какого браузера, устройства или через VPN;
- одна подпись комиссии принимается в реестр один раз;
- по желанию — лимит на IP (`MAX_VOTES_PER_IP`) и ограничение частоты запросов.

Идентификация — в `server/identity.js`.

## Ограничения

- Человек с несколькими SIM-картами сможет проголосовать несколько раз — по разу с каждого номера.
- Ключи комиссии хранятся на сервере. В настоящем ДЭГ ключ расшифровки делится между членами комиссии (схема Шамира).
- Оператор сервера по логам теоретически может сопоставить время выдачи подписи и время отправки бюллетеня.
- После публикации итогов квитанция позволяет увидеть свой расшифрованный бюллетень (как в ДЭГ) — её не стоит никому показывать.
