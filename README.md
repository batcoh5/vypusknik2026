# Выпускник 2026 — сайт голосования

Сайт народного голосования проекта «Выпускник 2026» (р.п. Краснообск).
Устроен по принципам ДЭГ (vybory.gov.ru), оформлен в стиле портала Госуслуг.

- один человек — один бюллетень;
- голос тайный: бюллетень заверяется **слепой подписью**, поэтому его нельзя связать с избирателем;
- выбор **шифруется в браузере** ключом комиссии, промежуточных итогов не видит никто;
- все бюллетени лежат в **открытом реестре** (цепочка блоков с хешами и подписями);
- после голосования избиратель получает **квитанцию** и может **проверить свой голос**;
- после завершения комиссия публикует ключ расшифровки, и любой может **пересчитать итоги сам** прямо в браузере.

## Запуск

Нужен Node.js 22.13 или новее. Внешних зависимостей нет: используются встроенные `node:sqlite` и WebCrypto.

```bash
ADMIN_TOKEN=придумайте-длинный-ключ npm start
# сайт: http://localhost:3000
```

Тесты: `npm test`.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт |
| `DATA_DIR` | `./data` | ключи комиссии (`keys.json`) и база (`vote.db`) |
| `ELECTION_CONFIG` | `./config/election.json` | номинации, участники, сроки |
| `ADMIN_TOKEN` | генерируется при старте | ключ для страницы `/admin` |
| `MAX_VOTES_PER_IP` | `0` (без лимита) | сколько бюллетеней можно выдать на один IP |
| `TRUST_PROXY` | — | `1`, если сайт стоит за nginx/балансировщиком (брать IP из `X-Forwarded-For`) |
| `SECURE_COOKIES` | — | `1` при работе по HTTPS |

В продакшене сайт должен работать по **HTTPS**: браузерная криптография (WebCrypto) доступна только в защищённом контексте.
Папку `data/` нужно резервировать и никому не передавать: в ней закрытые ключи комиссии.

### Настройка голосования

Номинации, участники и сроки задаются в `config/election.json`. Сейчас там заглушки («Участник 1» и т.д.) — их нужно заменить на реальные.
Не меняйте `id` номинаций и участников после начала голосования.

## Страницы

| Адрес | Что там |
|---|---|
| `/` | главная: статус, таймер, номинации, как защищён голос |
| `/vote` | голосование: подтверждение → бюллетень → проверка → отправка → квитанция |
| `/verify` | проверка голоса по номеру квитанции или файлу квитанции |
| `/ledger` | открытый реестр бюллетеней и проверка всей цепочки |
| `/results` | итоги (после завершения) и независимый пересчёт |
| `/admin` | для оргкомитета: статистика и досрочное завершение |

## Как это работает

```
Браузер избирателя                                Сервер
───────────────────                               ──────
1. token = случайные 32 байта
   blinded = H(token)·rᵉ mod n        ──────▶  2. проверка: этому избирателю
                                                  подпись ещё не выдавалась
                                      ◀──────     blindSig = blindedᵈ mod n
3. signature = blindSig · r⁻¹ mod n                (сервер не видит token)
4. ballot = ECIES(выбор, ключ комиссии)
5. {token, signature, ballot}         ──────▶  6. проверка подписи, token ещё не использован,
                                                  запись блока в цепочку, подпись блока
                                      ◀──────     квитанция = хеш блока
7. проверка хеша и подписи квитанции
```

- **Слепая подпись** — RSA-2048 с Full Domain Hash (схема Чаума). Реестр избирателей (`voters`) знает, кому выдана подпись, но не знает токен; реестр бюллетеней (`blocks`) знает токен, но не знает, кому он выдан.
- **Шифрование** — ECDH P-256 + HKDF-SHA-256 + AES-256-GCM. Открытый текст дополняется до 512 байт, чтобы длина шифртекста не выдавала выбор.
- **Реестр** — каждый блок содержит `SHA-256(index | время | хеш предыдущего | token | подпись | SHA-256(бюллетень))` и подпись ECDSA P-256. Удаление или замена блока ломает цепочку и обнаруживается на `/ledger`.
- **Подсчёт** — при завершении (по времени из конфига или кнопкой в `/admin`) сервер расшифровывает бюллетени, фиксирует итоги и хеш последнего блока и публикует закрытый ключ шифрования. Страница `/results` повторяет подсчёт в браузере.
- Вся проверяемая математика находится в одном модуле `public/js/core.js`, который используют и сервер, и браузер.

## Защита от повторного голосования

Сейчас (до SMS):

1. бюллетень выдаётся один раз на устройство — по подписанной httpOnly-cookie;
2. одна слепая подпись принимается в реестр ровно один раз (уникальный `token`);
3. при необходимости — лимит бюллетеней на IP (`MAX_VOTES_PER_IP`). Учтите, что вся школа может выходить в интернет с одного IP;
4. лимит частоты запросов к API.

Это базовая защита: очистка cookie или другой браузер позволяют получить ещё один бюллетень. Надёжно решит проблему подтверждение по SMS.

### Как подключить SMS

Идентификация вынесена в `server/identity.js`. Нужно добавить провайдер `phone`:

1. `POST /api/auth/phone` — принять номер, отправить код через SMS-шлюз, сохранить хеш кода с временем жизни и лимитом попыток;
2. `POST /api/auth/verify` — проверить код и выдать сессию, привязанную к номеру;
3. в `identify(req)` возвращать `keys.hmac('phone:' + номер)`.

Остальной код (слепая подпись, реестр, проверка) не меняется. Номера телефонов в реестре избирателей хранятся только в виде HMAC.

## Ограничения

- Ключи комиссии хранятся на сервере. В настоящем ДЭГ ключ расшифровки делится между членами комиссии (схема Шамира) — это можно добавить позже.
- Время блока округляется до минуты, но оператор сервера по логам запросов теоретически может сопоставить время выдачи подписи и время отправки бюллетеня.
- Квитанция после публикации ключа позволяет увидеть свой расшифрованный бюллетень (как в ДЭГ). Это значит, что квитанцию не стоит никому показывать.
